## Extraction / metric findings

Reuse v2 extraction rather than rebuilding it. It already has answer block selection,
boundary-aware mentions, source-only negatives, URL-token exclusion, citation entity
and occurrence separation, candidates and complete/partial channel semantics.
That is **implemented plumbing, not human-validated extraction**.

Publication must select versioned feature contracts and retain both positive partial
evidence and unavailable exhaustive metrics. Legacy LLM numerator counts matching
alias entries; denominator is `greatest(items_count, 1)` and value is binary presence.
It cannot be relabelled as answer-mention share. For `outcome_status='available'`
and `items_count=0`, current legacy SQL deterministically produces `no_results`
availability with a nonnull metric value. That boundary conflicts with the release
validator's unavailable-null rule: a source-verified defect, not an observed current
production row. Add a boundary fixture and fix/version the contract before release.

Legacy Gold brand grain does not use the same approval filter as v2. Configured
brand rows have `TO_BE_VERIFIED` ownership and example names/domains. This audit
does not promote candidates or substitute real brands. Query↔prompt mappings
need human approval with rationale, context, reviewer and version, not guessed pairing.

Full contracts and quality gates must be approved per
[benchmark specification](ds0_extraction_benchmark_20261008.md) and
[implementation plan](v1_implementation_plan_20261008.md).
